# Setting up a new machine for this project

Everything needed to run the page, ask it a question locally, and ship the
backend. Written 2026-11-10.

**This repository is public.** No secret is written here — only where each one
is kept, and how to get another if it is lost. Nothing below is worth having
without the accounts behind it.

---

## What the project is

A static site (`index.html`, `css/`, `scripts/`, `assets/`) served by GitHub
Pages at `william-brendel.com`, and a small Node API in `server/` that answers
questions about the corpus in `server/data/markdowns/`. The API runs on one
t4g.micro in us-east-1 behind Caddy; see [server/DEPLOY.md](server/DEPLOY.md)
for the live details and the architecture.

Retrieval is local: a flat vector file, embedded with a bundled ONNX model. No
vector database, no vendor. The only paid call is Claude writing the answer.

---

## Back these up before the old machine goes

Two files, neither of them in git, neither downloadable again as-is.

| File | What it is | If it is lost |
|---|---|---|
| `server/.env` | Local development settings — the Anthropic key | Rebuild from `server/.env.example`; the production value is in AWS SSM Parameter Store, and a fresh key can be minted at console.anthropic.com |
| `~/.aws/credentials` entry for the deploy profile | The `pp` operator user's access key | Delete the old key in IAM and create another; nothing else depends on the value |

Everything else — the corpus, the vectors, the model cache — is either in git
or rebuilt by a command below.

## Install

```bash
xcode-select --install
brew install node awscli colima docker docker-buildx gh
```

**Node 24 or newer.** The deploy builds `node_modules` inside `node:24`, so a
local runtime far from that is asking for a surprise on the box.

**Colima**, once: `colima start`, then `colima stop`, then set `memory: 4` in
`~/.colima/default/colima.yaml`. The default holds far too much of a 16 GB
machine — read "Shipping from this Mac" in [server/DEPLOY.md](server/DEPLOY.md)
before you skip this. `ship.sh` starts and stops Colima by itself; it is not
meant to be left running.

**GitHub**: `gh auth login`. The server depends on a private `llms` package,
and `ship.sh` reads `gh auth token` to fetch it during the container build.

## The code

```bash
mkdir -p ~/Development/Projects/Crossroads-Lab && cd $_
git clone git@github.com:williambrendel/Personal-Page.git
cd Personal-Page/server && npm ci
```

Then `cp .env.example .env` and fill in `ANTHROPIC_API_KEY`. `.env` is
gitignored and must stay that way.

The embedding model is not in git. It downloads on first run into
`server/.model_cache` (`XENOVA_CACHE_DIR`), which takes a minute once.

## Running it locally

```bash
npm --prefix server run app
```

```bash
python3 -m http.server 8000
```

The API comes up on `:3002` after ~20s — it loads the ONNX model and the
vector store before it listens, so the first visitor never pays boot cost.
`scripts/api.js` points the page at `localhost:3002` whenever the hostname is
local, so the static server on `:8000` talks to it with no configuration.

Without the API the page still loads; the chat box reports that it cannot
reach the backend, and the starter chips fall back to a hardcoded three.

Useful while working on the corpus:

| Command | What it does |
|---|---|
| `npm --prefix server run ask "question"` | One question, straight through the engine, no HTTP |
| `npm --prefix server run verify` | Checks the vectors still match the markdown — **run this after any corpus edit** |
| `npm --prefix server run ingest` | Re-embeds the corpus and rewrites the manifest |
| `npm --prefix server run retrieve "question"` | What retrieval returns, with scores, before Claude sees it |

Section ranges are byte offsets into the markdown. Edit a file without
re-ingesting and the resolver returns misaligned text rather than an error —
which is why the server refuses to boot on a stale manifest.

## AWS

One profile, named `pp`, for an IAM user whose policy is deliberately narrow:
it can deploy and restart, and it cannot read the Anthropic parameter, create
identities, or launch anything bigger than a `t4g.small`. The policy is
generated by `server/infra/make-operator-policy.sh`, which fills the account
ID from STS at run time so it is never committed.

```bash
aws configure --profile pp        # access key for the personal-page-operator user
aws sts get-caller-identity --profile pp
```

The account ID, the bootstrap stack and what each permission is for are in
[server/DEPLOY.md](server/DEPLOY.md). GitHub Actions reaches the same account
by OIDC with no stored keys; the Mac deploy is the primary path and the
workflow is the backup.

## Deploying

```bash
AWS_PROFILE=pp npm --prefix server run ship -- --check
```

```bash
AWS_PROFILE=pp npm --prefix server run ship
```

`--check` runs every precondition and stops. The real run refuses unless the
working tree is clean and `HEAD` is exactly `origin/main` — what ships is what
is on GitHub, not what is on the desk.

The site deploys by pushing to `main`; Pages serves the repository root. **Ship
the API before pushing the site** whenever a change spans both, or the live
page briefly calls an endpoint that does not exist yet.

## Rules for this machine

It is shared with other projects. On 2026-11-10 a full disk killed a deploy
mid-test and an idle Colima holding ~5 GB of memory caused crashes on a
perfectly healthy disk.

1. **Colima only during builds.** `ship.sh` starts it only if it was down and
   stops it on exit, including after a failure. Otherwise `colima status` /
   `colima stop`.
2. **Disk first.** `ship.sh` refuses under 12 GB free. By hand:
   `df -h /System/Volumes/Data`, then `docker builder prune -f` and
   `colima ssh -- sudo fstrim -a` — without the trim, macOS never sees the
   space come back.
3. **Check before heavy work:** `memory_pressure | tail -1`. A VM does not
   show its real size in `ps`; use `top -l 1 -o mem -n 10 -stats pid,mem,command`.
4. **Never edit a bash script while it is running.** Bash reads it as it goes.
5. **Never delete** another project's Docker images or containers, any Docker
   volume, `~/Library/Application Support/Claude/vm_bundles`, or anything in
   the user's files, Downloads or Trash.
